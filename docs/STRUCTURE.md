# Folder structure

## Placement rule

- **`core/domain/`**: entities and contracts used by **two or more features** (`MediaItem`, `Genre`, `MediaRepository`, `UserLibraryRepository`…).
- **`features/<x>/domain/`**: entities and contracts **private to that feature** (`MatchRoom` is only used by `matcher`).
- Each feature has three layers, and dependencies only point inward: `presentation → domain ← data`. `domain` never imports Flutter, Firebase, Dio, or another feature (only `core/domain`).
- `data` implements `domain`'s contracts and is the only place where TMDB / Firestore / SQLite DTOs exist.

## `presentation/` internal layout (applies to every feature)

Every feature's `presentation/` folder follows the same internal shape,
regardless of feature size:

```
presentation/
  <feature>_screen.dart      thin — assembles sub-widgets, provides the Cubit
  cubit/
    <feature>_cubit.dart      states live in the same file unless it grows
                               past rule 11's soft limit (150 lines), in
                               which case split into <feature>_state.dart
  widgets/
    <thing>_a.dart            one sub-widget per file (rule 11)
    <thing>_b.dart
```

Name the subfolder `cubit/` (not `bloc/`) when the feature uses a plain
`Cubit`, matching the flutter_bloc package's own convention — reserve
`bloc/` only for the rare screen that genuinely needs event-driven `Bloc`
(see CLAUDE.md's state convention, e.g. the Matcher's room lifecycle).

## Technical decisions the structure assumes

| Topic | Choice | Note |
|---|---|---|
| State | `flutter_bloc` | One `Cubit` (or `Bloc` for screens with real event flows) per screen in `presentation/`. |
| DI | `get_it` + `injectable` | Repositories and services are annotated (`@LazySingleton(as: SomeRepository)`) on their implementation class; `injectable_generator` (via `build_runner`) writes the actual `getIt` registrations into `app/di.config.dart`. `main()` only calls `configureDependencies()`. Cubits/Blocs are NOT annotated/registered — they're created where the screen is built and pull dependencies via `getIt<T>()`. |
| Navigation | go_router | Needed for Matcher deep links (`app://room/K7PM3Q`) and sharing. |
| HTTP | Dio | Interceptors for bearer auth, `language`/`region`, and logging. |
| Persistence | drift (SQLite), backed by the `sqlite3` package | Typed, migrations, queries for Stats. Use `sqlite3` (≥ 3.6.0) directly — `sqlite3_flutter_libs` is deprecated, do not add it. |
| Models | Hand-written immutable classes in `domain`; `freezed` optional for DTOs | Keeping the domain free of codegen makes it readable in review. |
| Serialization | `json_serializable` only in `data/` | |

If you'd rather choose differently on any row (Isar instead of drift, plain get_it instead of injectable), the structure doesn't change — only the contents of `presentation/` and `core/persistence/`.
